# V1.3 — R2 staging -> local Strix -> R2 delivery

## Recommended data path

1. Square checkout completes.
2. Verified Square webhook authorizes fulfillment.
3. Customer completes product-specific intake.
4. Customer receives `intake/upload.html?order=...&intake=...`.
5. Browser uploads files **directly to private Cloudflare R2**:
   - `incoming/<order>/<intake>/<uuid>-<filename>`
   - small files: signed PUT
   - large video: multipart, 100 MiB parts, resumable per-part
6. `/upload/ready` writes a job manifest:
   - `jobs/ready/<job-id>.json`
7. The local EVO-X2 / Strix bridge polls R2 over outbound HTTPS.
8. The Strix claims the job, downloads source files to:
   - `/home/mike/socal-ai/data/store_orders/<job-id>/source/`
9. It writes a task into the existing SoCal AI task inbox.
10. Local SoCal AI processes AIM/video and writes deliverables to:
    - `/home/mike/socal-ai/data/store_orders/<job-id>/output/`
11. `publish_delivery.py` uploads outputs to:
    - `delivery/<order>/<job-id>/`
12. A delivery service mints short-lived signed GET URLs for the customer.
13. Lifecycle rules automatically remove temporary staging and eventually delivered assets.

## Security

The Strix box is not exposed to the public Internet. It only makes outbound HTTPS calls to R2.
R2 credentials live only in:
- Cloudflare Worker secrets, and
- a protected local environment file on the Strix.

Customers receive only short-lived signed upload/download URLs.

## Storage recommendation

Use one private R2 Standard bucket initially, `socaln-media`, with prefixes instead of multiple buckets.

Suggested retention:
- incoming source: 14 days
- job markers: 30 days
- customer delivery: 90 days
- local source: preserve per your local media retention policy

For high-volume permanent video archive, reconsider Backblaze B2 or local NAS because raw R2 storage is $0.015/GB-month after the free tier.

## Important production hardening

- The Worker must confirm the order is actually paid before issuing upload credentials.
- Restrict allowed extensions/MIME types and maximum purchased upload quota.
- Add malware scanning for arbitrary document/archive uploads.
- Add customer authentication or one-time intake token.
- Record checksums.
- Use multipart upload for video.
- Do not use a public R2 bucket for customer source or report delivery.
